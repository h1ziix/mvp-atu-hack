# ATU EcoVision · мобильное приложение

Expo SDK 58, React Native, TypeScript, Expo Router. Приложение рассчитано на **Expo Go**: native-модули выбраны из состава Expo Go, `prebuild`, Xcode и Android Studio не требуются. Папки `ios/` и `android/` не генерируются.

## Запуск

```sh
bun install
bunx expo start --go
```

Откройте проект в Expo Go с поддержкой SDK 58, отсканировав QR-код из терминала. Для веб-проверки: `bun run web`.

## Два режима данных

Без настроек Supabase автоматически включается локальная демоверсия. На экране входа доступны пять организаций из спецификации. Пароль: `atu2026`. Записи, новые виды отходов, статусы и черновики сохраняются на устройстве. Данные организаций и периодов изолированы.

Для общей базы создайте `.env.local` на основе `.env.example`:

```dotenv
EXPO_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

Загрузите предоставленную схему `supabase_schema_and_seed.sql` в свой проект Supabase отдельно. Приложение использует её RPC `authenticate_user`, `add_organization_waste_type`, витрину `v_organization_waste_catalog` и таблицы `reports`, `waste_records`, `status_history`, `disposal_methods`, `organizations`. Коэффициенты и конвертация массы совпадают с исходной схемой. Статусы и записи обновляются через Supabase Realtime; подписки удаляются при смене отчёта. Также данные обновляются при возвращении приложения на передний план и по свайпу вниз.

После изменения окружения перезапустите Expo. При переключении между демо и сервером сохранённый вход сбрасывается. В клиенте допустим только публичный ключ; `service_role` сюда не добавлять. `.env` и `.env*.local` исключены из Git.

Авторизация реализована по RPC из ТЗ, а не через Supabase Auth. Предоставленная SQL-схема содержит открытые политики для демо: для промышленного развёртывания потребуется отдельная серверная авторизация и RLS. Клиент соблюдает блокировки, но не заменяет серверный контроль доступа.

## Реализовано

- Вход по почте и паролю, быстрый вход в пять организаций, подстановка по `?org=iskander` и `?qr=atu-qr-iskander`, QR-сканер.
- Русский и казахский интерфейсы, сохранение языка, карточка организации и ответственного лица, выбор месяца.
- Шаблоны на 6 / 3 / 6 / 3 / 8 видов отходов, семь способов утилизации, автоподстановка единицы и рекомендуемого метода.
- Взвешивания: добавление, просмотр, редактирование, удаление, поиск, фильтр за сегодня, даты лабораторных занятий.
- Проверка веса `0 < amount <= 2000`, даты в выбранном периоде и не в будущем; предупреждение о вероятном дубле с возможностью продолжить.
- Локальное сохранение несохранённых полей при каждом изменении, восстановление после закрытия или перезапуска. При ошибке отправки поля сохраняются. Серверные изменения без интернета не считаются сохранёнными.
- Новый вид отхода с категорией, единицей, пригодностью к переработке и вторым языком. Без перевода используется исходное название на обоих языках; машинный перевод не имитируется.
- Дневные и месячные итоги, масло `1 л = 0,92 кг`, строка ТПП «тара + кости», фактическая экономия CO₂ по выбранному методу и потенциальная по рекомендации.
- Отправка отчёта, блокировка `submitted` / `in_review` / `approved`, комментарий возврата, повторная отправка, таймлайн. В локальном демо есть явно обозначенные кнопки проверяющего.
- Фото с камеры или из галереи. Изображения сохраняются в `photo_url` как data URL (разрешённый спецификацией вариант), чтобы не зависеть от настройки Storage bucket. Фото автоматически уменьшается и сохраняется как JPEG ограниченного размера.

## M4: фото, перевод, голос и весы

AI-функции реализованы через **Supabase Edge Function `smart-input`** с DeepSeek V4 Flash. Приложение отправляет фото или текст после входа; ключ провайдера хранится в Supabase Secrets. Фото уменьшается до 1280 px, результат проверяется и подтверждается перед заполнением формы. Диктовка использует системную клавиатуру/Web Speech, затем AI-разбор текста. Новый вид можно перевести между RU/KZ прямо в форме.

Для весов предусмотрен HTTP-шлюз с проверкой стабильности, свежести и единиц. Если шлюз не указан, остаются явно обозначенные демонстрационные весы.

Инструкции публикации, Secrets, авторизация и формат API — в [docs/STAGE_M4.md](docs/STAGE_M4.md).

## Проверки

```sh
bun run lint
bun run typecheck
bun run test
bunx expo-doctor
bunx expo export --platform all --output-dir /tmp/atu-mobile-export
```

Тесты покрывают валидацию, блокировки, шаблоны пяти организаций, дубли, массу масла, CO₂, спец-итог ТПП, QR и разбор RU/KZ фраз. UI проверен в браузере на ширине 360 px: вход, ошибка веса и восстановление, сохранение, новый вид, дубли, восстановление черновика после перезагрузки, отправка и возврат, переключение языка. Для проверки реальной камеры, диктовки клавиатуры и системных разрешений откройте приложение в Expo Go на телефоне.

Изменения интерфейса и применённые UI/UX-навыки описаны в [docs/UI_UX.md](docs/UI_UX.md).
